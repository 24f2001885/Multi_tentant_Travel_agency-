1. Executive Summary & Architecture Overview

Between Milestone P7 and Milestone P11, TMA evolved from a single-tenant monolith into an enterprise-grade multi-tenant SaaS travel and expedition engine. The platform provides complete logical isolation between organizations while maintaining a shared database architecture with subdomain and custom-domain routing.

Core Isolation Guarantee
Every tenant's data is guarded by the TenantScopedMixin, contextual scopes (tenant_context), and host-only session cookies. Even under malicious parameter injection or direct ID referencing, requests cannot read or mutate data belonging to other organizations.

2. Milestone-by-Milestone Summary of Built Features

Milestone P7: Tenancy Core & Security Hardening

  • Subdomain & Domain Resolver: Dynamically routes <subdomain>.localhost:5000 and custom apex domains to their corresponding Organization records.
  • Platform Admin Control Plane: Hosted on a dedicated host (platform.localhost:5000) for superadministrators to onboard, manage, and suspend tenant organizations.
  • Host Barrier Isolation: Platform admin endpoints return HTTP 404 when requested from a tenant subdomain; tenant endpoints return HTTP 404 when requested from the platform domain.
  • Auth Hardening: Standardized E.164 mobile number normalization via Google's phonenumbers library, mandatory Terms of Service acceptance gate (terms_accepted_at), and host-only session cookies.

Milestone P8: Identity, RBAC & Access Governance

  • Capability Catalog: Granular permission system covering treks, bookings, payments, staff management, role administration, and marketing campaigns.
  • Custom Role Builder: Tenant owners can create custom roles (e.g. Lead Guide, Logistics Manager) with fine-grained capability checkboxes.
  • Protected Capabilities Guard: Critical administrative permissions (such as roles.manage, staff.manage, and organization settings) can only be accessed by the Tenant Owner. Non-owner staff attempting to assign or execute protected actions receive HTTP 403 / 422.
  • Session Snapshot Caching: Fast capability checks cached directly in the user session for minimal database load.

Milestone P9: Booking Engine v2 & Money Platform

  • Multi-Participant Bookings: Capture detailed participant profiles, dietary restrictions, medical conditions, and emergency contacts for all travellers on a booking.
  • Promotional Coupons: Percentage and flat discounts with max uses, minimum order thresholds, and strict tenant isolation.
  • Tiered Refund Policy: Automatic, rule-based cancellation refunds based on time windows prior to trek departure.
  • Automated Tax Invoicing & WeasyPrint PDF: Sequential invoice numbering per organization with tax breakdown (GST) and on-the-fly downloadable PDF generation.
  • Automated Waitlist FIFO Engine: Automated slot progression when bookings are cancelled, offering open spots to waitlisted travellers within a timed window.
  • Razorpay Route Integration: Marketplace split payments between the platform and tenant vendors with webhook processing for automated settlements.

Milestone P10: Trek Content, Discovery & Itineraries

  • Structured Daily Itineraries: Multi-day schedules with categorized elements (activities, meals, transport, accommodations, notes).
  • Vector PDF Itinerary Export: Customer-facing printable brochure generation with day-by-day breakdowns.
  • Media Gallery & EXIF Stripping: Upload handling with Pillow-based automatic removal of EXIF and GPS coordinates for privacy, storing files with unique UUIDs.
  • Staff Trek Origination: Staff can draft treks that land in a "pending" queue; only tenant admins can approve and publish inventory.
  • Verified Reviews: Trek reviews gated strictly to travellers who completed their trip, with masked public reviewer names (e.g., "Rahul K.").

Milestone P11: Communication Platform & Messaging Compliance

  • Omnichannel Dispatch Gateway: Single entry point dispatch() handling Email, SMS, and WhatsApp Cloud API.
  • Critical Notification Carve-Out: Transactional operational alerts (booking confirmation, cancellations, waitlist offers, OTPs) bypass marketing preference opt-outs.
  • Consent & Preference Management: Granular opt-in ledger (NotificationConsent), channel toggles, and RFC 8058 one-click unsubscribe links/headers.
  • Marketing Message Campaigns: Target audiences filtered by past trek history, with safety test-sends required before launch and recipient delivery tracking.
  • Meta WhatsApp Cloud API Webhook: Verification challenge handling and HMAC-SHA256 signature verification with real-time delivery status updates.

3. Local Machine Runbook (Step-by-Step)

Step 1: Configure Windows Hosts File

Open C:\Windows\System32\drivers\etc\hosts in Notepad (as Administrator) and add:

127.0.0.1 platform.localhost
127.0.0.1 tenantzero.localhost
127.0.0.1 a.localhost
127.0.0.1 b.localhost

Step 2: Environment File (.env)

Ensure your .env file is in the root directory (copied from .env.example). The default development settings work out of the box:

FLASK_APP=app:create_app
FLASK_ENV=development
SECRET_KEY=dev-secret-key-tma-multi-tenant
HASHIDS_SALT=dev-salt-hashids-tma

DATABASE_URL=postgresql://tma:tma_dev_password@db:5432/tma_platform
TEST_DATABASE_URL=postgresql://tma:tma_dev_password@db_test:5432/tma_platform_test

BASE_DOMAIN=localhost
PLATFORM_ADMIN_HOST=platform.localhost
TENANT_ZERO_NAME=Summit Expeditions
TENANT_ZERO_SUBDOMAIN=tenantzero

PLATFORM_ADMIN_NAME=Platform Owner
PLATFORM_ADMIN_EMAIL=owner@platform.local
PLATFORM_ADMIN_PASSWORD=PlatformOwnerPass123!
ADMIN_EMAIL=admin@tma.local
ADMIN_PASSWORD=AdminPass123!

EMAIL_PROVIDER=smtp
MAIL_SERVER=mailhog
MAIL_PORT=1025
MAIL_DEFAULT_SENDER=no-reply@tma.local
SMS_PROVIDER=twilio
WHATSAPP_PROVIDER=meta_cloud_api

Step 3: Start Docker Containers

docker compose build
docker compose up -d

Step 4: Execute Database Migrations & Seeds

# 1. Apply all database migrations (Baseline through P11)
docker compose exec web flask db upgrade

# 2. Seed Platform Superadmin
docker compose exec web flask seed-platform-admin

# 3. Seed Tenant Zero (default organization & primary subdomain)
docker compose exec web flask seed-tenant-zero

# 4. Seed the initial Tenant Administrator
docker compose exec web flask seed-admin

# 5. Seed the RBAC Capability Catalog and starter roles
docker compose exec web flask seed-rbac

# 6. Backfill communication consents for legacy accounts
docker compose exec web flask backfill-consents

Step 5: Access Web Interfaces

  • Platform Superadmin: http://platform.localhost:5000 (Login: owner@platform.local / PlatformOwnerPass123!)
  • Tenant Zero Portal: http://tenantzero.localhost:5000 (Login: admin@tma.local / AdminPass123!)
  • MailHog Mailbox: http://localhost:8025 (Captures all outgoing confirmation & invoice emails)

5. Zero-Cost Development Mode

Testing Without Live Accounts

You can run and test 100% of the platform right now without paying or awaiting third-party approvals:

  • Payments: Razorpay test keys (rzp_test_...) provide dummy cards for instant checkouts and refunds.
  • Email: Local mailhog container on port 1025 captures all outbound emails. View them in your browser at http://localhost:8025.
  • WhatsApp & SMS: In development mode without API credentials, the notification service safely prints all outbound payloads to the console/container log without raising exceptions.
